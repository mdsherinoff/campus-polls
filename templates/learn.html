Counting votes without reading them

Campus Polls uses the Paillier cryptosystem (Pascal Paillier, 1999). Its special property: multiplying two ciphertexts gives an encryption of the sum of the two hidden numbers. So the server can add up every encrypted ballot and only ever decrypt the final total.

Below is the real algorithm with tiny numbers so every step can be followed by hand. The live poll uses exactly the same steps, with 2048-bit keys (numbers over 600 digits long).

Each voter encrypts 1 for "yes, this candidate" or 0 for "no".

Reveal one step at a time while you explain it.

  1. The election authority makes a key pair

    Pick two secret primes p and q. Their product n is the public key; it is sent to every phone. The private key (λ and μ) can only be computed by someone who knows p and q.

  2. A ballot is a row of locked boxes: one 1, the rest 0

    Think of a ballot as one locked box per candidate. The voter puts a 1 in the box of the candidate they choose and a 0 in every other box, then locks every box with the public key. Anyone can lock a box, but only the authority's private key can open one.

    The server receives only the locked boxes. They all look like random numbers, so it cannot tell which box holds the 1, and a vote for A looks just like a vote for B. To count, the server takes one candidate's column and combines those boxes (the next steps show how). The result is a single locked box holding that candidate's total, and only that total is ever opened.

    The rest of this page follows the Candidate A column, with the votes you picked above. The live poll repeats it for every candidate.

  3. Each phone encrypts its vote

    For a vote m and a fresh random number r the textbook formula is c = gm · rn mod n². We use g = n + 1, which turns it into the form our code actually runs:

    c = (1 + m·n) · rn mod n²

    The vote m sits inside (1 + m·n). The part rn is a random mask, so encrypting the same vote twice gives different ciphertexts and nobody can spot "all the 1s" by comparing ballots.

  4. The server multiplies the ciphertexts

    The server never decrypts a single ballot. It just multiplies them together:

    Why multiplying adds the votes. Multiply the vote parts of two ballots:

    (1 + a·n)(1 + b·n) = 1 + (a + b)·n + a·b·n²

    The last term is a multiple of n², so it disappears under mod n². What is left is 1 + (a + b)·n: the votes have been added. The masks multiply into one new mask, r₁n · r₂n = (r₁r₂)n, so the total stays hidden too.

  5. The authority decrypts only the total

    Using the private key: m = L(Cλ mod n²) · μ mod n, where L(x) = (x − 1) / n.

  6. Why an attacker cannot do the same

    To decrypt you need λ = lcm(p − 1, q − 1), which needs p and q. Everyone knows n, so the whole system rests on one question: given n, can you find p and q? This is the integer factorisation problem. Paillier's formal security assumption, the Decisional Composite Residuosity problem (telling whether a number is an n-th power mod n²), is believed to be just as hard.

  7. What this costs

    Privacy is not free. Time to encrypt one vote, measured with tools/benchmark.py (the bars use a log scale, so a bar that looks only a bit longer is many times slower):

    AES-256-GCM
    0.001 mscannot add
    RSA-2048
    0.023 mscannot add
    Paillier-2048
    5.1 mscan add

    Counting is cheap. Adding 10,000 encrypted ballots and decrypting the total takes 65.6 ms on the server. The slow part, encryption, happens once on each voter's own phone.

    Paillier is about 200 times slower than RSA for one vote, but it is the only one of the three that lets the server add votes it cannot read. Measured with 2048-bit keys on an arm64 laptop, Python 3.14.2.
